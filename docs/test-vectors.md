# Test vectors (RFC 8251)

The 12 `testvectorNN.bit` files under
`tests/Kiln.Audio.Tests/Fixtures/opus_testvectors/` are the RFC 8251 conformance vectors. They
are committed (3.5 MB, 3,529,642 bytes); the `.dec` reference decodes are generated by
`scripts/fetch-test-vectors.sh`. See `SOURCE.md` there for provenance and the tarball SHA-256.

## `.bit` format

Each file is a headerless sequence of records:

| Bytes | Meaning |
|---|---|
| 4 | packet length, big-endian |
| 4 | encoder final range, big-endian |
| *length* | the Opus packet, starting at its TOC byte |

`OpusBitFile.Read` (`tests/Kiln.Audio.Tests/Oracle/OpusBitFile.cs`) exposes each record as
`(byte[] Packet, uint FinalRange)`. `OpusPacket.TryParse` validates each packet and splits it
into frame ranges (RFC 6716 §3.2).

## Choosing a target

- **SILK-only:** 02 (NB), 03 (MB), 04 (WB). All four SILK frame durations (10/20/40/60 ms).
- **CELT-only:** 01 and 11 (FB), 07 (NB/WB/SWB/FB). All four CELT frame durations
  (2.5/5/10/20 ms).
- **Hybrid-only:** 05 (SWB), 06 (FB), both at 10/20 ms.
- **Mixed mode:** 08 and 09 (SILK + CELT), 10 (Hybrid + CELT), 12 (SILK + Hybrid). A decoder
  lane that switches modes in one stream can use these.
- **Stereo-only:** 01, 11. **Mono-only:** 12. Every other vector contains both.
- **Frame-count codes:** 02–07 and 12 use only code 0 (one frame per packet). Codes 1, 2 and 3
  all appear in 01 and 08–11, so those vectors exercise every packet layout.
- **Bandwidths:** NB, MB, WB, SWB and FB all appear; MB appears only in SILK (03) and in the
  SILK portion of 12.

This is a TOC census only: it says which modes and sizes a vector contains, not what the
decoded samples should be.
